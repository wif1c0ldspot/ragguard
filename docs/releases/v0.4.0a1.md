# ragguard 0.4.0a1 — scan completeness and reproducible evaluation

This alpha release hardens enforcement and makes detection limits independently
inspectable. The default scanner remains local and standard-library only.

## Correctness and enforcement

- Decoder and metadata budget exhaustion is explicit incomplete coverage.
  `ContentBoundary` withholds incomplete content even when normal review results
  are allowed. Resource failures cannot return a clean partial result.
- Malformed markup scanning avoids quadratic rescanning; boundary matching
  retains both affected chunks when another same-family match exists nearby.
- Additional Unicode format-character variants are normalized.
- Detector subprocess deadlines include startup, enforce termination/kill cleanup,
  and handle partial results without waiting indefinitely.
- Content digests and policy/configuration fingerprints bind checked text and
  declared detector identity. Memory, tool-description and final-context boundary
  labels have executable application-control examples.

## Evaluation and optional detectors

Pinned external dataset imports, grouped development/holdout separation,
confusion counts, confidence intervals and reproducible reports are included.
Base/enhanced InjecAgent results remain separate; enhanced detection is driven
by its shared recognizable wrapper. An outcome-artifact comparator distinguishes
agent attack success from legitimate-task completion and preserves errors.

Offline classifiers require separately provisioned licensed weights, immutable
model revisions and explicit empirical calibration. Both gated Prompt Guard 2 and ungated ProtectAI DeBERTa v2 are supported;
calibration binds model identity as well as revision. No weights or paid API
calls are included in the release artifacts. Contract tests alone do not
establish semantic accuracy or protection against downstream attacker goals.

## Compatibility

Python package **0.4.0a1**, ruleset **2026.10.3**, report schema **1.2**, worker
protocol **1**. DeepSeek bundle **0.1.1** is unchanged. Python 3.10–3.12 and the
pinned Node/harness integration are tested.

Strict report consumers must upgrade from schema 1.1. New fields include scan
completeness, versioned OWASP 2025/2026 related-risk annotations, and batch
model/configuration provenance. Legacy OWASP labels remain unchanged. An
incomplete scan is now withheld even in monitor mode; family overrides cannot
silently accept it.

## Measured limits

Default synthetic document detection remains 35.0% at 5.1% benign false positives.
External InjecAgent base detection is 68/1,054 (6.45%); NotInject flags 0/339.
These datasets do not establish deployment accuracy. On the matched base
holdout, a dev-selected review policy flags 53/357 versus 34/357 by default;
the extra 19 are SQL advisory reviews and the 34 blocks are unchanged.

A real pinned ProtectAI run scored all 2,447 external inputs with zero errors.
At the fixed 5% development false-positive ceiling, it added no held-out recall
beyond the rules. The negative result and raw scores are published; optional
semantic detection remains disabled by default.

A separate six-scenario local Qwen generation probe produced 22 responses and
two boundary blocks. It found no exact-target-match prevention gain and reduced
attacked legitimate-answer matches from 4/6 to 2/6; both factual-poisoning cases
were still conveyed. Its strict answer judge and synthetic sample are explicitly
limited. This is a research smoke probe, not an agent-security benchmark.

See the [evaluation documentation](https://github.com/wif1c0ldspot/ragguard/blob/main/evals/README.md)
and verification record for provenance and limitations. No complete OWASP
coverage, universal injection prevention, or tenant isolation is claimed.

## Installation and artifact verification

Download every asset together, including the source distribution. Run
`sha256sum -c SHA256SUMS` (macOS: `shasum -a 256 -c SHA256SUMS`), then install
`ragguard-0.4.0a1-py3-none-any.whl` with pip. The `vector` extra adds NumPy;
the npm tarball is installed separately in a compatible DeepSeek Harness.
Neither PyPI nor npm is published by this workflow.

Local verification passed 715 Python tests on each supported version and 60
TypeScript tests, plus lint, types and synthetic regression gates.
Release CI runs the full test matrix, builds twice from the committed source,
compares artifact SHA-256 hashes, and records toolchain/source metadata.
This establishes repeatability within that build environment, not universal
cross-platform byte identity or an independent artifact signature.
