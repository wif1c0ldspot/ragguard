# ragguard 0.3.0 — public analysis and integration foundations

This alpha release keeps the default scanner local and dependency-free. It adds
an optional provider-neutral semantic detector interface, evaluation provenance
and holdout checks, a retrieval-to-context example, and public contribution and
security reporting guidance.

## Added

- `SemanticDetector` adapters on `RAGPipelineGuard`, bounded input/output validation,
  fail-closed failures, per-occurrence latency and optional adapter-reported usage.
  No model, provider client, paid service or measured semantic recall is bundled.
- Provenance-labelled evaluation manifests, frozen holdout hashes, separate chunk
  evaluation and validation for application-supplied external corpora.
- Executable collection-authorized retrieval, final-render scanning, review/error
  withholding and minimal audit output.
- Contributor guide, threat model, private security reporting and issue templates.
- Pinned CI actions, dependency-update configuration and verified release artifacts.

## Included hardening since the initial public snapshot

- Chunk reconstruction and policy decisions for both affected chunks.
- Deferred-context mutation protection in the DeepSeek integration.
- Enforced re-embedding budgets and corrected Python CI matrix selection.

## Compatibility and limits

Python package: **0.3.0**, ruleset: **2026.10.2**, report schema: **1.1**, worker
protocol: **1**. DeepSeek npm bundle: **0.1.1**, targeting the exact harness peer
versions declared in its manifest. Python 3.10, 3.11 and 3.12 and Node 22 are tested.
Existing default scanner and JSON report behavior is preserved.

The bundled synthetic document benchmark still reports **35.0% attack detection**
and **5.1% benign false positives**. Semantic tests use deterministic stubs, not a
real model benchmark. No clean scan guarantees safety or tenant isolation.

## Installation and verification

Download all release assets together and run `sha256sum -c SHA256SUMS`
(macOS: `shasum -a 256 -c SHA256SUMS`), then install the wheel with pip. Add the
`vector` extra for numpy-backed assessments. The npm tarball is installed separately
in a compatible DeepSeek Harness environment. Neither registry is published by
this release process.

The workflow runs the full CI suite before publishing, builds artifacts twice
and compares SHA-256 hashes, and includes `build-info.json` with the source commit
and tool versions. Reproducibility is verified within the build environment;
cross-platform byte identity and independent artifact signatures are not claimed.
