# ragguard 0.4.0a2 — architecture and evaluation correctness

This alpha release separates domain types and normalization from the scanner,
preserving established imports. It corrects evaluation accounting, detector audit
visibility and bounded vector/metadata behavior. Detection quality remains limited.

## Correctness changes

- Incomplete scans and evaluation errors remain unknown rather than credited as
  detected attacks. Reports preserve full denominators and uncertainty bounds;
  quality gates reject incomplete evaluations and invalid threshold configuration.
- Raw detector exception messages no longer appear in normal chained tracebacks.
  Single-document APIs retain detector usage and model/configuration provenance.
- Numeric metadata consumes the character budget; oversized integer conversion is
  bounded. Identical normalized vectors pass an exact fidelity threshold, and
  cross-owner assessment computes only eligible pairs within its comparison budget.
- Paired outcome schema 2 requires matching generation settings and a common
  pre-defense input digest. Historical schema 1 artifacts are retained unchanged.
- Release verification installs and exercises the exact final wheel and npm archive
  before publication, after two builds produce matching SHA-256 hashes.

## Compatibility and dependencies

Python package **0.4.0a2**, report schema **1.3**, ruleset **2026.10.3.1**, worker
protocol **1**. Strict report consumers must accept per-document `detector_runs`.
The base package remains standard-library only; vector assessment requires NumPy.

The optional Python 3.12/macOS ARM evaluation runtime now uses PyTorch 2.14.0,
Transformers 5.10.1 and SentencePiece 0.2.2. The standalone mpmath 1.4.1 proposal
was corrected: SymPy requires mpmath below 1.4, so the compatible runtime retains
1.3.0. CI checks the full pinned environment resolves together. Historical pins
are retained as JSON provenance rather than recommended installation instructions.

## Measurements

The existing 316 document and 32 chunk regression cases complete without unknown
results; their detection counts are unchanged. New pinned classifier and paired
generation measurements are stored separately from the historical reports:

- `evals/reports/semantic-protectai-current.json`
- `evals/reports/rag-probe-current/`

The upgraded-runtime measurements still show no incremental classifier recall at
the fixed development false-positive ceiling and no exact-target prevention gain
in the six-scenario generation probe. Semantic detection remains disabled by
default. These are bounded research measurements, not production guarantees.

Download all release assets together and verify `SHA256SUMS` before installing
`ragguard-0.4.0a2-py3-none-any.whl`. Neither PyPI nor npm publication is performed.
